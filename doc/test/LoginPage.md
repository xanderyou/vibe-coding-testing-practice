> 狀態：初始為 [ ]、完成為 [x]
> 注意：狀態只能在測試通過後由流程更新。
> 測試類型：前端元素、表單驗證、Mock API、路由導向、AuthContext 狀態

---

## [x] 【前端元素】應該正確渲染登入表單元素
**範例輸入**：無
**期待輸出**：畫面上顯示電子郵件輸入框、密碼輸入框及登入按鈕。

---

## [x] 【表單驗證】輸入無效的電子郵件格式時，應該顯示錯誤訊息
**範例輸入**：email 輸入 "invalid-email"
**期待輸出**：顯示錯誤訊息「請輸入有效的 Email 格式」，且不會觸發登入 API。

---

## [x] 【表單驗證】輸入長度不足 8 個字元的密碼時，應該顯示錯誤訊息
**範例輸入**：email 輸入 "test@example.com", password 輸入 "1234567"
**期待輸出**：顯示錯誤訊息「密碼必須至少 8 個字元」，且不會觸發登入 API。

---

## [x] 【表單驗證】輸入不含英文字母或數字的密碼時，應該顯示錯誤訊息
**範例輸入**：email 輸入 "test@example.com", password 輸入 "abcdefgh" 或 "12345678"
**期待輸出**：顯示錯誤訊息「密碼必須包含英文字母和數字」，且不會觸發登入 API。

---

## [x] 【Mock API】輸入正確的帳號密碼時，應該成功登入並導向至 /dashboard
**範例輸入**：email 輸入 "test@example.com", password 輸入 "test1234"，點擊登入
**期待輸出**：登入 API 呼叫成功，且路由導向至 `/dashboard`。

---

## [x] 【Mock API】登入失敗時，應該顯示 API 回傳的錯誤訊息
**範例輸入**：登入 API 回傳錯誤訊息 "帳號或密碼錯誤"
**期待輸出**：畫面上顯示錯誤橫幅 "⚠️ 帳號或密碼錯誤"。

---

## [x] 【前端元素】提交表單時，應該顯示載入中狀態並禁用表單
**範例輸入**：輸入正確格式後點擊登入按鈕並等待 API 回應
**期待輸出**：按鈕文字變為 "登入中..."，且電子郵件、密碼輸入框與按鈕皆被禁用（disabled）。

---

## [x] 【路由導向】若使用者已登入，造訪登入頁應該自動導向至 /dashboard
**範例輸入**：AuthContext 的 `isAuthenticated` 為 true
**期待輸出**：自動導向至 `/dashboard`。

---

## [x] 【AuthContext 狀態】若有登入過期訊息，應該顯示該訊息並清除狀態
**範例輸入**：AuthContext 的 `authExpiredMessage` 有值 "登入狀態已過期"
**期待輸出**：畫面上顯示錯誤訊息 "登入狀態已過期"，並呼叫 `clearAuthExpiredMessage`。

---

## [x] 【環境變數】當沒有 VITE_API_URL 時，應該顯示測試帳號提示
**範例輸入**：環境變數 `VITE_API_URL` 未設定
**期待輸出**：畫面底部顯示「測試帳號：任意 email 格式 / 密碼需包含英數且8位以上」的提示區塊。

---

## [x] 【表單驗證】再次送出表單時，應該先清除前一次的 API 錯誤訊息
**範例輸入**：畫面上已有登入失敗的錯誤訊息，使用者再次點擊登入按鈕
**期待輸出**：API 發送請求前，畫面上的錯誤訊息應該先被清除。
